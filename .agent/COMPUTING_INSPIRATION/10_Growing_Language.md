# 10. Growing a Language - OOPSLA Conference

**Speaker**: Guy Steele  
**URL**: https://www.youtube.com/watch?v=lw6TaiXzHAE
**Duration**: 54 minutes, 12 seconds  
**Channel**: Computer History Museum

---

This talk, delivered by Guy Steele, emphasizes that programming languages, much like human languages, must be designed for growth rather than being initially small or large (13:34). He argues that a language needs to provide ways for users to define new words and rules that integrate seamlessly, making it easier for a community to contribute to its expansion (22:36). Steele advocates for a "bazaar" style of language development, where the design can evolve based on user needs and contributions (27:50), as opposed to a rigid "cathedral" approach. He uses the Java programming language as a prime example, suggesting it should incorporate features like generic types and overloaded operators to facilitate user-driven growth (35:08).

Here are the key takeaways from the talk:

Small vs. Large Languages: A language should not be designed as fixed, either small or large, but rather with the capacity to grow over time (13:34).
The "Worse is Better" Philosophy: A small, imperfect language released quickly can gain widespread adoption and then evolve, as users will not wait for a perfectly designed language (17:43).
Facilitating User Contribution: A language's design should allow users to define new words and functionalities that appear as seamless as built-in features, enabling community-driven growth (20:20).
"Bazaar" vs. "Cathedral" Development: The "bazaar" approach, where many users contribute and the design adapts in real-time, is more effective for language growth than a rigid "cathedral" master plan (25:52-28:12).
The Importance of Patterns: Language design should move from designing a fixed "thing" to designing a "pattern" for growth, allowing for flexibility and future adaptation (31:34-31:41).
Proposed Java Features for Growth: Steele advocates for adding generic types (33:18) and overloaded operators (34:54) to Java to empower users to extend the language effectively and naturally (35:08-35:22).
Empowering Users to "Fish": Instead of pre-defining every possible feature (like 20 kinds of number types), the language should provide tools that enable users to create these features themselves, fostering broader adoption and utility (46:26-47:11).
